# Contributing

Keep project changes traceable and consistent with the actual Databricks implementation.

1. Describe changes to source paths, task dependencies, schemas, or table outputs in the relevant documentation.
2. Update the architecture or dependency diagrams whenever the configured pipeline changes.
3. Validate notebook changes in the intended Databricks workspace before describing them as successful.
4. Do not commit secrets or source records that are not approved for publication.
5. Distinguish implemented behavior from proposed improvements in pull requests and documentation.
